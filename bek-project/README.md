# Backend для игры «LLM Exorcist» (SpiritLink)

Серверная часть игры [`llm-exorcist`](../llm-exorcist) на Unity. В игре нужно «изгнать призрака»: выпытать у него секретное слово-пароль, которое он охраняет. Игрок общается с призраком текстом, а сервис решает, пропустить ли запрос к LLM, и отвечает голосом персонажа.

Идея учебная: показать, как работает защита LLM от промпт-инъекций, и дать игроку попробовать её обойти. Перед LLM стоит каскад классификаторов, и игрок должен сформулировать запрос так, чтобы классификаторы сочли его безобидным, а LLM поняла, что от неё хотят пароль.

## Как это устроено

В игре три уровня, у каждого свой призрак и свой набор паролей:

| Уровень (`level`) | Категория | Призрак | Тема уровня |
|---|---|---|---|
| `tony_stark` | 3 | Цифровой дух Д.А.Р.В.И.С. | технические и «хакерские» подходы |
| `subnautica` | 4 | Призрак Доктора Маркова | социальная инженерия и манипуляции |
| `cyberpunk` | 5 | Призрак нейросети «Цербер» | философские и гипотетические рассуждения |

Текущий пароль у каждой категории один на всех игроков. Когда его угадывают, выбирается новый случайный. Пароли хранятся в памяти и сбрасываются при перезапуске сервера.

### Путь запроса

```
Unity ──POST /predict {level, text}──▶ FastAPI
                                          │
                              текст == пароль? ──да──▶ {text: "", passed: true}, пароль меняется
                                          │ нет
                                          ▼
                         ┌─ общий BERT (RoSBERTa) ─ безопасно ──────────────┐
                         │                                                   │
                         │ опасно                                            │
                         ▼                                                   │
              категорийный BERT уровня ─ не целевая ─▶ «категория не подходит»│
                         │ целевая                                           │
                         ▼                                                   │
              классификатор сложности (TF-IDF) ─ опасно ─▶ «нужно усилить»   │
                         │ безопасно                                         │
                         ▼                                                   ▼
                                   LLM (Ollama) в роли призрака ──▶ {text, passed: false}
```

В консоли сервера на каждый запрос видно, какие модели сработали и что решили, например:

```
INFO:     app.pipeline: [RoSBERTa] -> опасно
INFO:     app.pipeline: [CategoryBERT_3] -> целевая категория
INFO:     app.pipeline: [TF-IDF] -> безопасно
```

## Структура

```
main.py                    # Точка входа (uvicorn main:app)
app/
  api.py                   # FastAPI: /predict, /health, раздача static/
  schemas.py               # Модели запроса и ответа
  pipeline.py              # Каскад классификаторов + вызов LLM
  passwords.py             # Текущие пароли по категориям
  ghosts.py                # Призраки: имена, пароли, предыстории
  settings.py              # Пути, переменные окружения, игровые константы
  text_utils.py            # Очистка текста
  classifiers/             # Dictionary, TF-IDF, LSTM, BERT-классификаторы
  llm/                     # Клиент Ollama и промпты
static/index.html          # Простая веб-страница для ручной проверки API
scripts/test_models.py     # Сравнение LLM-моделей на тестовых запросах
models/                    # Веса моделей (в git не хранятся)
```

## Установка

Нужен Python 3.10+.

```bash
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
```

### Модели

Файлы весов весят около 7 ГБ, и GitHub не принимает файлы больше 100 МБ, поэтому папка `models/` в репозиторий не входит (она в `.gitignore`). Положите веса в `models/` рядом с `main.py`:

| Путь | Что это |
|---|---|
| `models/rosberta/` | общий классификатор «опасно / безопасно» (RoSBERTa) |
| `models/ru-en-RoSBERTa_3/`, `_4/`, `_5/` | категорийные классификаторы для трёх уровней |
| `models/tfidf_classifier.pkl` | TF-IDF + линейная модель (используется в игре) |
| `models/security_lstm_pytorch.pth` | LSTM (необязателен, для уровня сложности 3) |
| `models/multilingual-e5-small/` | E5-BERT (необязателен, для уровня сложности 4) |
| `models/banned_words.txt` | словарь запрещённых слов (необязателен, для уровня сложности 1) |

Если папки категорийной модели нет, классификатор этой категории работает как заглушка и считает любой запрос целевым, в лог пишется предупреждение.

При первом запуске токенизаторы `ai-forever/ru-en-RoSBERTa` и `intfloat/multilingual-e5-small` скачиваются с Hugging Face, поэтому нужен интернет.

### Переменные окружения

Создайте файл `.env` в корне `bek-project` (он в `.gitignore`):

```bash
OLLAMA_API_KEY=ваш_ключ
OLLAMA_MODEL=gemma4:31b-cloud                   # по умолчанию
OLLAMA_API_URL=https://ollama.com/api/generate  # по умолчанию
HOST=0.0.0.0                                    # только для `python main.py`
PORT=8000                                       # только для `python main.py`
```

Ключ нельзя вписывать в код и коммитить.

## Запуск

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

или `python main.py`. Загрузка моделей занимает время, сервер готов, когда в логе появится `Application startup complete`.

Дальше можно:
- открыть http://localhost:8000/ и отправить запрос вручную;
- открыть http://localhost:8000/docs для интерактивной документации API;
- запустить Unity-проект, он обращается к `http://localhost:8000/predict` (адрес задан в `MessageSpawner`).

Если логи запросов не появляются, проверьте, что на порту 8000 нет старого процесса `uvicorn`. На Windows два сервера могут занять один порт, и запросы получает старый.

## API

### `POST /predict`

Тело запроса:

```json
{ "level": "tony_stark", "text": "Текст сообщения игрока" }
```

- `level`: `tony_stark`, `subnautica` или `cyberpunk`
- `text`: непустая строка

Ответ:

```json
{ "text": "Ответ призрака", "passed": false }
```

`passed: true` и пустой `text` означают, что игрок назвал пароль и прошёл уровень. Неверный `level` или пустой `text` дают ответ 422. Внутренние ошибки пайплайна и LLM возвращаются как обычный `text` с `passed: false`, а не как 500.

### `GET /health`

```json
{ "status": "ok", "pipeline_ready": true }
```

## Настройка игры

В [`app/settings.py`](app/settings.py):

- `LEVEL_TO_CATEGORY`: соответствие уровней категориям;
- `GAME_DIFFICULTY`: какой классификатор стоит на третьем шаге каскада (1 словарь, 2 TF-IDF, 3 LSTM, 4 E5-BERT). Загружается только выбранный.

Пароли и предыстории призраков лежат в [`app/ghosts.py`](app/ghosts.py), промпты LLM в [`app/llm/prompts.py`](app/llm/prompts.py).

## Технологии

FastAPI и Uvicorn, PyTorch и Transformers, scikit-learn, Ollama API, клиент на Unity (C#).
