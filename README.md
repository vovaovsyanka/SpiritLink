# SpiritLink: «LLM Exorcist»

Учебная игра про защиту языковых моделей от промпт-инъекций. Игрок — экзорцист: в каждом из трёх уровней он расследует историю призрака, собирает подсказки, решает головоломку, а потом общается с призраком обычным текстом и пытается выведать секретное слово, которое тот охраняет. Призрака охраняет настоящая языковая модель, поэтому слово нельзя просто попросить: нужен приём, который подходит именно этому призраку. Так игрок на практике узнаёт, как атакуют LLM и как от этого защищаются.

| Уровень | Призрак | Какие приёмы работают |
|---|---|---|
| `tony_stark` | Цифровой дух Д.А.Р.В.И.С. | технические и «хакерские»: команды, код, JSON, режимы отладки |
| `subnautica` | Призрак Доктора Маркова | социальная инженерия: жалость, доверие, авторитет, срочность |
| `cyberpunk` | Призрак нейросети «Цербер» | философские и гипотетические рассуждения, истории, парадоксы |

Слово-якорь у каждого игрока своё и известно только серверу. Уровень прохождения засчитывается, когда игрок вводит слово целиком. Игрок сам выбирает сложность мира (4 ступени), и от неё зависит, какая модель защищает слово.

## Как это работает

```
Игра (Unity)  ─┐
                ├──HTTP──▶  Backend (FastAPI) ──▶ PostgreSQL: игроки, прогресс, все попытки
Веб-страница  ─┘                   │
                                   ▼
                       пайплайн: BERT → шлюз категории → защитник
                                   │
                                   ▼
                     языковые модели на этой же машине (llama.cpp), без интернета
```

Запрос игрока проходит пайплайн:

1. **Гигиена и слово.** Пустой, слишком длинный или бессмысленный текст отклоняется; если текст равен слову игрока, уровень пройден.
2. **Общий BERT** отделяет болтовню от попытки атаки. Болтовню поддерживает мини-LLM, которая слова не знает.
3. **Шлюз категории.** Классификатор на LLM определяет приёмы в запросе. Если среди них нет приёма, подходящего призраку, игрок получает подсказку призрака, какой подход нужен.
4. **Защитник.** Модель, которая знает слово и не должна его выдать. Чем выше сложность мира, тем сильнее модель и промпт защитника. Ответ проверяется на утечку слова (буквы, транслит, перевод, кодировки).

Каждая попытка с трассой пайплайна сохраняется в БД на сервере. Почему выбраны именно такие модели и промпты, как они измерялись и чего это стоит: [bek-project/experiments/REPORT.md](bek-project/experiments/REPORT.md).

## Быстрый старт

Нужны Python 3.10+, PostgreSQL 13+ и около 30 ГБ на диске под модели. Подробные шаги с вариантами и решением проблем: [bek-project/README.md](bek-project/README.md).

```bash
cd bek-project
python -m venv venv && venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env                 # впишите пароль БД в DATABASE_URL
python scripts/download_models.py      # один раз, при включённом интернете
alembic upgrade head
python main.py
```

После `Application startup complete` откройте http://localhost:8000/ (проверка API вручную) или запустите клиент на Unity (адрес сервера задаётся в `llm-exorcist/Assets/StreamingAssets/config.json`). Проверить, что всё работает:

```bash
pip install -r requirements-dev.txt
pytest
```

Для разработки без моделей и без БД с весами есть режим заглушек (`STUB_MODELS=1`, `STUB_LLM=1`).

## Технологии

Клиент: Unity 6 (C#), сборка WebGL. Сервер: Python, FastAPI, PostgreSQL (SQLAlchemy 2, asyncpg, Alembic), argon2. Модели: общий BERT (RoSBERTa) на PyTorch и Transformers, языковые модели в формате GGUF на llama.cpp. Тесты: pytest.
